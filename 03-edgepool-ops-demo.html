§2 — Local setup (6 bước)

# 1. Yêu cầu: Node ≥ 20.19, npm ≥ 10 (không bắt buộc RPC key — ledger dự phòng vẫn đủ 250 giao dịch)
cp backend/.env.example backend/.env        # điền secrets thật (không commit)
cp frontend/.env.example frontend/.env      # optional
# 2. Install riêng
cd backend && npm install && cd .. && cd frontend && npm install && cd ..
# 3. DB qua Docker
docker compose up -d postgres
docker inspect fomo-postgres --format='{{.State.Health.Status}}'  # healthy
# BE tự migrate + seed 10 ví master khi bảng rỗng. Tránh container api-harness-postgres-1 (:5434).
# 4. Chạy split (2 terminal)
npm run dev:backend    # :3000
npm run dev:frontend   # :3001 → mở http://localhost:3001
# 5. Smoke (tất cả phải xanh)
curl -s http://localhost:3000/api/health
curl -s "http://localhost:3000/api/portfolio/transactions?limit=2" | head -c 600
curl -N -s http://localhost:3000/api/onchain/stream | head -n 5
curl -s http://localhost:3001/api/health   # qua FE rewrites
# 6. Typecheck / build
npm run typecheck && npm --prefix frontend run build

§3 — Docker runbook + troubleshooting

docker compose up -d --build && docker compose ps
docker compose logs -f backend
docker compose logs -f frontend
docker restart fomo-backend
docker compose down              # giữ data — không dùng -v (mất dữ liệu PG)
LỗiCách fix
BE crash-loop “can't reach postgres”Xem postgres đã healthy chưa; BE tự hồi sau 10–20s.
Migrate failĐọc log entrypoint, fix migration rồi up -d --build backend.
:3001/api/health đỏ, :3000 xanhSai BACKEND_URL — trong compose phải là http://backend:3000.
Port bận 5433/3000/3001Kiểm tra process chiếm cổng (ss -ltnp | grep -E '5433|3000|3001'); dừng hẳn pm2 cũ (pm2 delete all) trước khi chuyển sang Docker.
FE build OOMBuild riêng frontend, tăng swap, hoặc build 1 lần rồi up không --build.
Lưu ý quan trọng: docker compose down -v (mất volume DB). Đổi .env phải up -d <service> — restart thường không đọc lại env_file.

§5 — Kịch bản demo 5 phút

Không cần ví crypto khi demo — đăng nhập bằng tài khoản seed ở tab Tài khoản. Mật khẩu thật chỉ nằm trong backend/.env trên server.

PhútLàm gìCâu chốt
0–1 terminalMở FE: brand Edgepool, leaderboard ví thật, chart PnL, ticker.“Track 10 smart-money Solana realtime — SSE live, không dùng dữ liệu giả.”
1–2 userLogin user (USER): chỉ chart/swaps/positions-read/VaultCard read.“PnL-first; nút Send/Copy/History ẩn theo role — authz thật ở BE.”
2–3 paperĐăng nhập admin → tab Bots: tick gần nhất có 2 lệnh CONFIRMED; CopyHistory 12 orders + devnet signature.“1-click paper devnet, lifecycle PENDING→CONFIRMED, gate/cap đầy đủ.”
3–4 vaultVaultCard: Share/HWM/Queued + PARTNER EARNINGS (partner 0.30, treasury 0.10 — đúng 80/15/5). Mở GET /api/vaults/1/earnings nếu cần chi tiết.“Phí 20% trên lãi mới vượt đỉnh; KOL thấy được phần của mình.”
4–5 auditAdminPanel users/audit/vaults: gán role KOL trực tiếp, audit append-only (cả login_failed).“Paper-only sandbox. On-chain vault + cash-out là phase sau.”

Tài khoản: admin / $SEED_ADMIN_PASSWORD (ADMIN) · user / $SEED_USER_PASSWORD · kol / $SEED_KOL_PASSWORD. Dự phòng khi mất mạng ví: dùng CopyHistory có sẵn + SSE tự reconnect. Đổi mật khẩu trước khi công khai.

§6 — Launch hub (sandbox → production)

Nguyên tắc: cap nhỏ trước, mở dần, mọi bước có tiêu chí pass + rollback. Hiện tại hệ thống chạy paper/sandbox hoàn toàn.

Nhánh Analyst (triển khai trước)

A0–A1: nền dữ liệu prod-grade, chất lượng tín hiệu, UX/API analyst, vận hành đọc. Thu hút người dùng và dữ liệu, không cần tiền thật.

Nhánh Product (chạm tiền người dùng)

P0–P1 hardening web + custody/key → P2–P3 vault + execution → P4 beta tiền thật giới hạn. Hoàn thành P1–P3 trước khi tiếp xúc tiền thật.

Điểm chung: auth/roles (tài khoản + ví), audit append-only, FE shell, policy/window engine, demo-sim sandbox training. Chi tiết: docs/setup/LAUNCH_RUNBOOK*.md.
